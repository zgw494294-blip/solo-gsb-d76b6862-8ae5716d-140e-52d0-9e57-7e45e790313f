# 步道坡线规划台

本地运行的步道纵坡规划小工具：在网页上编辑等间距（1 m）测点的地面标高、
输入步道净宽，后端用 Python / FastAPI 计算满足坡度与水平段约束的最优方案
标高，并对可行方案做土方调配核算（分段积分挖填方、沿中点调配净流量与
运量距离）。页面叠画地面坡线与方案坡线，并列出每段高差、水平段、总调整量
与分段挖填、累计净量和调配流向；另提供测点可锁定标高分析：逐点给出
单独锁定该点方案标高时仍能补全为完整可行坡线的精确标高区间。方案旁附
**施工验收**：把当前地面、净宽下已算完的可行方案**冻结**后录入实测标高与
容差（0～20 整数厘米），后端只做逐项核对（不对实测重新求优），返回逐点
偏差、超容差点、实测高差超 8 cm 段、无水平段的连续 5 段窗口与首尾不符点，
全部无违规才可在页面确认验收。

- 前端：原生 HTML / CSS / JavaScript（Canvas 绘图，无框架、无构建步骤）
- 后端：Python + FastAPI，动态规划求最优解

## 一条命令启动

需要已安装 Docker（含 Compose 插件）。在项目根目录执行：

```bash
docker compose up --build
```

启动后浏览器访问：

```
http://localhost:8000
```

端口为 **8000**（容器内 `8000` 映射到宿主机 `8000`，见 `docker-compose.yml`）。
后台运行可加 `-d`，停止用 `docker compose down`。

## 不使用 Docker 的本地启动方式

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问地址同样为 <http://localhost:8000>。

## 规划规则

| 项目 | 规则 |
| --- | --- |
| 测点数量 | 3～16 个，等间距 1 m |
| 地面标高 | 0～200 的整数厘米 |
| 方案标高 | 0～200 的整数厘米 |
| 步道净宽 | 0.5～10 米，最多两位小数 |
| 首尾约束 | 方案首、尾标高必须分别等于地面首、尾标高 |
| 相邻高差 | 相邻方案点高差绝对值 ≤ 8 cm |
| 水平段要求 | 任意连续 5 段中至少有 1 段水平段（相邻方案标高相等） |
| 优化目标 | 总调整量 Σ\|方案标高 − 地面标高\| 最小 |
| 同分裁决 | 取方案标高序列字典序最小者 |

测点不足 6 个（少于 5 段）时，“任意连续 5 段”约束自动不触发。

## 页面与接口说明

- 顶部表格编辑各测点地面标高，可增删测点（受 3～16 个限制）；
  首尾测点的方案标高固定等于地面标高。修改后自动重新计算。
- 图中：**棕色虚线**为地面坡线，**绿色实线**为方案坡线，
  水平段在方案线上以**蓝色点划**叠加标出。
- 结果区列出各点地面/方案标高及差值、各段高差（正为抬升、负为下降）、
  水平段标记、水平段数量、最大相邻高差与总调整量。
- **可锁定区间**列（各点标高表内）：单独把该测点方案标高锁定为区间内
  任意整数厘米时，其余测点仍能补全为满足全部规则的完整坡线
  （不限总调整量，也不要求与当前最优方案一致）；区间外的值均不可行。
  区间为升序、互不相邻的整数闭区间，空档不填平；首尾测点固定为地面标高。
  测点变化时自动重算；非法输入或全线无解时，旧区间随结果一并清空，
  并由提示条说明原因。
- **土方调配核算**区列出：总挖方、总填方、全线净量（正为净余、负为净缺）、
  运量距离；每段的挖方、填方、段净量、累计净量与段内挖填变号交点位置；
  以及起点→首段中点、相邻中点之间的有向净流量（正值朝终点方向）。
  修改地面标高或净宽后自动重算；非法输入或无可行方案时，旧的核算结果
  会连同方案结果一并清除。
- 非法输入（数量越界、非整数、超出 0～200、净宽越界或超过两位小数等）
  或问题无解时，页面以提示条给出中文原因；无解时会区分“坡度约束本身
  不可达”（含首尾高差超限说明）与“水平段约束无法同时满足”。

## 施工验收

计算结果旁的**施工验收**卡用于现场复核，核心原则是“先冻结、再核对、
不重新求优”：

1. **冻结方案**：只能冻结与当前地面、净宽一致、且已算完的可行方案
   （无可行方案或输入非法时冻结按钮禁用）。冻结后测点表出现橙色
   “实测”行，录入与方案等数量的实测标高（0～200 整数厘米），并填写
   容差（0～20 整数厘米）。
2. **自动复核**：实测或容差修改后自动请求 `/api/acceptance`，页面叠画
   冻结方案（绿）与实测坡线（橙），列出逐点偏差（实测−方案）与四类违规；
   **全部无违规**时复核通过，“确认验收”按钮才可用。
3. **编辑即失效**：
   - 修改实测或容差：立即清空复核报告、撤销已确认状态，需重新复核通过
     才能再次确认；冻结方案不变；
   - 修改地面标高或净宽：冻结方案与全部实测一并废弃（实测行消失），
     重新冻结时会清除旧实测、报告与确认；
   - 迟到的规划、复核响应一律丢弃，不能恢复已失效的数据或启用确认；
   - 复核输入非法或请求失败时，只清空报告、撤销并禁用确认，**不改冻结
     方案**。
4. 验收只核对、不优化：冻结方案本身会被独立复核（长度、标高、首尾及
   原坡度/水平段约束），但不要求它是当前最优解；后端不会对实测或方案
   重新求解。

### 施工验收接口

`POST /api/acceptance` 接收**原地面、冻结方案、实测标高、容差**四个字段：

```bash
curl -X POST http://localhost:8000/api/acceptance \
  -H 'Content-Type: application/json' \
  -d '{"ground":[50,50,50,50,50,50],
       "plan":[50,52,52,51,50,50],
       "measured":[50,53,52,51,50,50],
       "tolerance":2}'
```

- 后端先独立复核冻结方案对原地面合法（长度与地面一致、标高 0～200 整数、
  首尾分别等于原地面首尾、相邻高差 ≤ 8 cm、任意连续 5 段至少 1 段水平；
  规则判定与规划同源，但**不调用求解器、不要求方案最优**），再校验实测
  等数量且为 0～200 整数、容差为 0～20 整数。
- `200` 返回（无论是否通过）：

```json
{
  "passed": true,
  "ground": [50, 50, 50, 50, 50, 50],
  "plan": [50, 52, 52, 51, 50, 50],
  "measured": [50, 53, 52, 51, 50, 50],
  "tolerance": 2,
  "deviations": [0, 1, 0, 0, 0, 0],
  "over_tolerance_points": [],
  "over_grade_segments": [],
  "no_horizontal_windows": [],
  "endpoint_mismatches": []
}
```

  - `deviations`：逐点偏差（实测减方案，厘米）；
  - `over_tolerance_points`：`|偏差| > 容差` 的点（恰好等于容差不算超），
    每项 `{index, plan, measured, deviation}`；
  - `over_grade_segments`：实测相邻高差绝对值超过 8 cm 的段，每项
    `{index, from, to, delta}`；
  - `no_horizontal_windows`：实测坡线中不含水平段的连续 5 段窗口
    （不足 5 段时不触发），每项
    `{index, from_segment, to_segment, segments:[…]}`；
  - `endpoint_mismatches`：实测首、尾与方案首、尾不相等的点，每项
    `{index, plan, measured}`；
  - 四个列表全为空时 `passed=true`。违规示例（`passed=false`）：

```json
{
  "passed": false,
  "deviations": [5, 1, 0, 0, 0, -9],
  "over_tolerance_points": [
    {"index": 1, "plan": 50, "measured": 55, "deviation": 5},
    {"index": 6, "plan": 50, "measured": 41, "deviation": -9}
  ],
  "over_grade_segments": [],
  "no_horizontal_windows": [],
  "endpoint_mismatches": [
    {"index": 6, "plan": 50, "measured": 41}
  ]
}
```

- `400`：请求体不是合法 JSON，或缺少 `ground` / `plan` / `measured` /
  `tolerance` 任一字段。
- `422`：输入非法（地面/方案/实测数量不一致、非 0～200 整数、容差非
  0～20 整数、方案首尾不等于原地面、方案违反 8 cm 高差或连续 5 段水平
  约束），`reason` 说明原因。接口是**无状态的纯核对**：每次请求独立
  校验，“冻结/确认/失效”生命周期完全由前端按上述编辑规则管理。

HTTP 接口（也可直接调用）：

```bash
curl -X POST http://localhost:8000/api/plan \
  -H 'Content-Type: application/json' \
  -d '{"ground":[100,107,114,119,124,130],"width":1.5}'
```

- `200` 且 `feasible=true`：返回 `plan`、`segments`、`horizontal_indices`、
  `total_adjustment`，以及 `width` 与土方核算 `earthwork`。
- `200` 且 `feasible=false`：输入合法但无可行方案，`reason` 说明原因，
  不返回 `earthwork`。
- `400`：请求体不是合法 JSON，或缺少 `ground` / `width` 字段。
- `422`：输入非法（数量/类型/取值范围、净宽非法），`reason` 说明原因。

### 测点可锁定标高分析接口

`POST /api/lockable` 只接收地面标高（不需要 `width`），校验规则与
`/api/plan` 完全相同：

```bash
curl -X POST http://localhost:8000/api/lockable \
  -H 'Content-Type: application/json' \
  -d '{"ground":[100,107,114,119,124,130]}'
```

可行时返回 `200` 且 `feasible=true`，`points` 按测点顺序给出精确的
可锁定标高集合，压缩为升序、互不相邻的整数闭区间（空档不填平）：

```json
{
  "feasible": true,
  "ground": [100, 107, 114, 119, 124, 130],
  "points": [
    {"index": 1, "intervals": [[100, 100]]},
    {"index": 2, "intervals": [[100, 100], [106, 108]]},
    {"index": 3, "intervals": [[106, 108], [114, 116]]},
    {"index": 4, "intervals": [[114, 116], [122, 124]]},
    {"index": 5, "intervals": [[122, 124], [130, 130]]},
    {"index": 6, "intervals": [[130, 130]]}
  ]
}
```

- `intervals` 中每个 `[lo, hi]` 为闭区间：锁定该测点方案标高为区间内
  任意整数时，其余测点必能补全为完整可行坡线；区间外则不能。
  相邻区间之间至少隔一个缺失值（如第 2 点的 101～105 不可锁定，
  不会用 `[100, 108]` 填平）。
- 全线无解时返回 `200` 且 `feasible=false`，`reason` 说明原因，
  不返回 `points`；输入非法时返回 `422`，缺少 `ground` 或请求体
  不是合法 JSON 时返回 `400`。

`earthwork` 字段结构（体积单位 m³，距离 m，运量距离 m³·m，全程不取整）：

```json
{
  "width": 1.5,
  "total_cut": 0.021,
  "total_fill": 0.036,
  "total_net": -0.015,
  "segments": [
    {"index": 1, "cut": 0.0, "fill": 0.0, "net": 0.0,
     "cumulative_net": 0.0, "cross_at": null}
  ],
  "flows": [
    {"index": 1, "from": "start", "to": "midpoint:1",
     "flow": 0.015, "distance": 0.5},
    {"index": 2, "from": "midpoint:1", "to": "midpoint:2",
     "flow": 0.015, "distance": 1.0}
  ],
  "transport_work": 0.06
}
```

- `cross_at` 为段内挖填变号交点距该段起点的距离（米），无变号时为 `null`；
- `flow > 0` 表示该边净流量朝终点方向；首边 `flow > 0` 表示经起点向线内
  运入（全线净缺），`flow < 0` 表示余量回流起点运出（全线净余）；
- `transport_work = Σ |flow| × distance`（起点至首段中点 0.5 m，其余 1 m）。

## 算法

合法转移与边界语义只有一份实现（`planner.step_rule` / `height_bounds`，
`lockable` 直接引用，不再各写一套）：给定当前点的最近 4 段水平位掩码
`mask`、当前标高与下一标高、所放段号，统一判定该转移是否合法
（0～200 值域、相邻高差 ≤ 8、连续 5 段窗口至少 1 段水平），并给出来到
下一点的新掩码；起点之前不存在的“虚拟段”视为水平（`INITIAL_MASK`），
使不足 5 段时不误触发约束；首尾固定由 DP 初值/边界保证。

带“最近 4 段是否水平”位掩码状态的动态规划：

- 后向成本 DP（`planner.backward_cost_dp`）：`dp[pos][mask][h]` 为第
  `pos` 点方案标高取 `h`、`mask` 打包此前最近 4 段水平状态时，后缀
  （含本点）的最小调整量；`dp` 值为无穷大同时表示“该状态无法合法补全
  到固定尾点”，所以这张表既是最优求解表也是后向可达性表，被
  `/api/plan` 与 `/api/lockable` 共用；
- 重建最优路径时每点自低到高取第一个经 `step_rule` 合法、且仍为最优的
  标高，即得到同分下字典序最小的方案（与成本表同源，不会选出 DP 不认可
  的转移）。

16 个测点的最坏规模单次计算约 0.1 秒（纯 Python）。

### 可锁定标高分析

与最优求解共用同一状态模型（`pos`、最近 4 段水平位掩码 `mask`、标高
`h`）与同一转移语义，只做可行性判定：

- 前向布尔可达性 `fwd[pos][mask][h]`：能否从首点（标高固定）走到第
  `pos` 点且取标高 `h`（转移同样只经 `step_rule`）；
- 后向可达性直接复用最优求解的后向成本 DP：`dp[pos][mask][h]` 有限
  当且仅当从第 `pos` 点取标高 `h` 出发能走到尾点（标高固定）。

跨过第 `pos` 点的连续 5 段窗口由两侧共享的 `mask` 校验，因此第 `i` 点
可锁定 `h` 当且仅当存在 `mask` 使 `fwd[i][mask][h]` 与
`dp[i][mask][h]` 有限同时成立。两种结果同源于一张 DP 表与一套转移，
同一地面数据不会在最优方案与可锁定分析之间出现可行性冲突。逐点收集
全部可锁定标高后，把连续整数合并为升序、互不相邻的闭区间返回（空档不
填平）。16 个测点单次分析约 0.1 秒。

### 土方调配核算

- 每段长 1 m，段内地面、方案标高均按线性变化，定义高差
  `d(x) = (地面(x) − 方案(x)) / 100`（米，正为挖深、负为填深）。
  两端同号（含零）时按梯形积分；两端异号时在零点
  `x* = d0 / (d0 − d1)` 把该段拆成两个三角形，分别积分挖方与填方
  截面积，再乘以步道净宽得体积（m³）。标高厘米先除以 100 换算为米，
  计算过程不提前取整。
- 每段挖填先抵消，得段净量 `net = cut − fill`；土方视为集中在该段中点。
- 调配链为「起点（x=0）→ 段1中点 → 段2中点 → … → 段m中点」，
  末端封闭、全线净余或净缺只经起点进出。由各中点质量守恒与末端
  流量 0 自后向前唯一确定每条边的有向净流量 `q`（正为朝终点）：
  `q[k−1] = q[k] − net[k]`；故起点流量 `q[0] = −全线净量`。
- 运量距离 = 起点至首段中点（0.5 m）与各相邻中点间（1 m）的
  `Σ |q| × 距离`。

### 施工验收复核

验收不引入新的规则实现（`acceptance.py`）：冻结方案的合法性逐段经
`planner.step_rule` 判定（`INITIAL_MASK` 起始、首尾固定由调用前检查
保证），相邻高差与 0～200 值域同样复用规划常量；但**不调用
`backward_cost_dp` 等求解逻辑**，因此冻结方案无需是最优方案，只要本身
合法即可被复核。实测坡线只做统计性核对：逐点偏差 `measured − plan`、
超容差点（`|偏差| > tolerance`，等于不算超）、实测高差绝对值超 8 cm 的
段、不含水平段的连续 5 段窗口（段数不足 5 时窗口枚举为空，与规划语义
一致）、首尾与方案不一致的点。四类列表全空才 `passed=true`；实测标高
仍限 0～200 整数厘米，容差限 0～20 整数厘米。接口无状态，冻结/失效/
确认的生命周期只存在于前端。
